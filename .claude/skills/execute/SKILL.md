# 로드맵 실행

대상 로드맵: `$ARGUMENTS`

## 실행 절차

### Step 1. 로드맵 파일 선택 및 확인

**인자가 있는 경우:**
- `docs/roadmaps/` 에서 해당 파일을 찾아 로드

**인자가 없는 경우:**
- `docs/roadmaps/` 내 파일을 수정일 기준 최신순으로 나열하고 선택하게 한다:

```
실행할 로드맵을 선택해주세요:

  1. 2026-03-25-roadmap-trgt-mgnt.md (최신)
  2. 2026-03-24-roadmap-마감관리.md
  ...

번호를 입력하거나 파일명을 알려주세요.
(엔터만 누르면 1번을 실행합니다)
```

**로드맵 확인:**

선택된 로드맵의 제목, Phase 구성, 전체 Task 수를 요약하여 보여준다:

```
선택된 로드맵: {로드맵 제목}
파일: docs/roadmaps/{filename}

| Phase | 내용 | Task 수 | 완료 |
|-------|------|---------|------|
| Phase 1 | ... | N개 | M개 완료 |
| Phase 2 | ... | N개 | M개 완료 |

이 로드맵으로 작업을 진행할까요?
```

### Step 2. 실행 방식 선택

사용자에게 실행 방식을 묻는다:

```
실행 방식을 선택해주세요:

  1. 태스크별 실행 — 각 태스크마다 확인 후 진행 (기본)
  2. 일괄 실행 — 모든 미완료 태스크를 한번에 실행

어떤 방식으로 진행할까요? (1 또는 2, 기본: 1)
```

**태스크별 실행 선택 시 안내:**
```
[태스크별 실행 모드]
- 각 태스크 완료 후 결과를 확인하고 다음 진행 여부를 결정합니다
- 중간에 방향 수정이나 피드백 반영이 가능합니다
- 대화가 끊겨도 /execute로 이어서 진행할 수 있습니다
```

**일괄 실행 선택 시 안내:**
```
[일괄 실행 모드]
- 모든 미완료 태스크를 순서대로 연속 실행합니다
- 중간에 사용자 확인을 묻지 않고 진행합니다
- 단, 아래 경우에는 멈추고 사용자에게 확인합니다:
  · 의사결정이 필요한 설계 선택지가 있을 때
  · 실행 중 에러가 발생했을 때
  · DB 마이그레이션 등 되돌리기 어려운 작업 직전

일괄 실행을 시작할까요? (Y/N)
```

### Step 3. 진행 상황 파악

로드맵 md 파일 내 체크리스트(- [x] / - [ ])를 기반으로 진행 상황을 파악한다.

**완료된 태스크:**
- `- [x]` 또는 "완료 기록" 블록이 있는 Task → 건너뜀

**다음 실행할 태스크:**
- 첫 번째 미완료 Task를 찾아서 사용자에게 안내:

```
현재 진행 상황: Phase {N}의 Task {M} 까지 완료

다음 작업: Task {M+1}. {Task 제목}
- 작업 목표: {목표}
- 작업 범위: {파일 목록}
- 작업 모델: {sonnet/opus}

이 태스크를 시작할까요?
```

(일괄 실행 모드에서는 위 안내 없이 바로 실행)

### Step 4. 태스크 실행

**실행 규칙:**
- 로드맵에 명시된 작업 범위와 완료 기준을 준수한다
- 로드맵에 작업 모델이 명시되어 있으면 해당 모델 사용을 안내한다
- 이전 태스크의 "완료 기록"을 참고하여 컨텍스트를 확보한다
- CLAUDE.md 규칙을 준수한다

**태스크 실행 중:**
- 주요 결정 사항이나 선택지가 발생하면 사용자에게 확인한다 (일괄 모드에서도)
- 에러가 발생하면 원인과 대안을 제시한다

### Step 5. 태스크 완료 처리

태스크가 완료되면 **반드시** 아래 두 가지를 수행한다:

**5-1. 체크리스트 체크:**
로드맵 md 파일 내 해당 태스크의 체크박스를 완료로 변경:
- `- [ ] Task N-M` → `- [x] Task N-M`

**5-2. 완료 기록 작성 (필수):**
해당 Task 섹션 끝에 완료 기록 블록을 추가한다.
이 기록은 **다음 태스크가 컨텍스트를 이어받기 위한 용도**이므로 반드시 작성한다.

```markdown
> **완료 기록 (YYYY-MM-DD)**
> - 변경 파일:
>   - `파일경로` — 설명
> - 주요 결정: {작업 중 내린 기술적 결정}
> - 다음 태스크 참고: {다음 태스크가 반드시 알아야 할 정보 — 새로 만든 타입명, 변경된 API 경로, 주의할 의존성 등}
```

**기록 규칙:**
- **간결하게** — 파일 목록 + 핵심 결정 + 다음 참고사항만. 불필요한 설명 금지
- **다음 태스크 참고**는 가장 중요 — AI가 다음 태스크 시작 시 이 항목을 먼저 읽는다
- 일괄 실행 모드에서도 매 태스크마다 완료 기록을 작성한다 (생략 금지)

### Step 6. 다음 태스크 안내

**태스크별 실행 모드:**

```
Task {N-M} 완료!

다음 작업: Task {N-M+1}. {Task 제목}
- 작업 목표: {목표}
- 작업 모델: {sonnet/opus}

계속 진행할까요?
```

**일괄 실행 모드:**
- 안내 없이 바로 다음 태스크를 실행
- 단, Phase가 바뀔 때는 진행 상황을 간략히 출력:

```
--- Phase {N} 완료 ({M}개 태스크) → Phase {N+1} 시작 ---
```

**모든 태스크 완료 시:**
```
로드맵의 모든 태스크가 완료되었습니다!

완료 요약:
- 총 {N}개 태스크 완료
- 생성/수정된 파일: {N}개
- 소요 Phase: {N}개

로드맵 파일에 전체 완료 상태가 기록되었습니다.
```

## 중단/재개

- 대화가 끊기거나 중단된 경우, `/execute` 를 다시 호출하면 체크리스트 + 완료 기록 기반으로 자동으로 미완료 태스크부터 이어서 진행한다
- 이전 태스크의 "완료 기록"이 있으므로 컨텍스트 손실 없이 재개 가능

## 주의사항

- 로드맵에 없는 작업을 임의로 추가하지 않는다
- 완료 기록은 간결하되, 다음 태스크가 참고할 수 있을 정도의 정보를 포함한다
- 로드맵 md 파일을 직접 수정할 때 기존 내용을 훼손하지 않는다 — 추가만 한다
- 일괄 실행 모드라도 되돌리기 어려운 작업(DB 마이그레이션, 대규모 삭제 등) 전에는 반드시 사용자 확인
