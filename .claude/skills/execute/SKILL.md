# 로드맵 실행

대상 로드맵: `$ARGUMENTS`

## 실행 절차

### Step 1. 로드맵 파일 선택 및 확인

**인자가 있는 경우:**
- `docs/roadmaps/` 에서 해당 파일을 찾아 로드

**인자가 없는 경우:**
- `docs/roadmaps/` 내 파일을 수정일 기준 최신순으로 나열하고 선택하게 한다:

```
실행할 로드맵을 선택해주세요:

  1. 2026-03-25-roadmap-trgt-mgnt.md (최신)
  2. 2026-03-24-roadmap-마감관리.md
  3. 2026-03-18-roadmap-role-based-menu-access.md
  ...

번호를 입력하거나 파일명을 알려주세요.
(엔터만 누르면 1번을 실행합니다)
```

**로드맵 확인:**

선택된 로드맵의 제목, Phase 구성, 전체 Task 수를 요약하여 보여준다:

```
선택된 로드맵: {로드맵 제목}
파일: docs/roadmaps/{filename}

| Phase | 내용 | Task 수 | 완료 |
|-------|------|---------|------|
| Phase 1 | ... | N개 | M개 완료 |
| Phase 2 | ... | N개 | M개 완료 |

이 로드맵으로 작업을 진행할까요?
```

### Step 2. 진행 상황 파악

로드맵 md 파일 내 체크리스트(- [x] / - [ ])를 기반으로 진행 상황을 파악한다.

**완료된 태스크:**
- `- [x]` 또는 "완료 기록" 블록이 있는 Task → 건너뜀

**다음 실행할 태스크:**
- 첫 번째 미완료 Task를 찾아서 사용자에게 안내:

```
현재 진행 상황: Phase {N}의 Task {M} 까지 완료

다음 작업: Task {M+1}. {Task 제목}
- 작업 목표: {목표}
- 작업 범위: {파일 목록}
- 작업 모델: {sonnet/opus}

이 태스크를 시작할까요?
```

### Step 3. 태스크 실행

사용자가 승인하면 해당 태스크를 실행한다.

**실행 규칙:**
- 로드맵에 명시된 작업 범위와 완료 기준을 준수한다
- 로드맵에 작업 모델이 명시되어 있으면 해당 모델 사용을 안내한다
- 이전 태스크의 "완료 기록"을 참고하여 컨텍스트를 확보한다
- CLAUDE.md 규칙을 준수한다

**태스크 실행 중:**
- 주요 결정 사항이나 선택지가 발생하면 사용자에게 확인한다
- 에러가 발생하면 원인과 대안을 제시한다

### Step 4. 태스크 완료 처리

태스크가 완료되면 두 가지 작업을 수행한다:

**4-1. 체크리스트 체크:**
로드맵 md 파일 내 해당 태스크의 체크박스를 완료로 변경:
- `- [ ] Task N-M` → `- [x] Task N-M`

**4-2. 완료 기록 작성:**
해당 Task 섹션 끝에 완료 기록 블록을 추가:

```markdown
> **완료 기록 (YYYY-MM-DD)**
> - 생성/수정된 파일:
>   - `파일경로` — 설명
> - 주요 결정: {작업 중 내린 기술적 결정}
> - 다음 태스크 참고: {다음 태스크가 알아야 할 정보}
```

### Step 5. 다음 태스크 안내

완료 기록 작성 후 다음 태스크로 이동:

```
Task {N-M} 완료!

다음 작업: Task {N-M+1}. {Task 제목}
- 작업 목표: {목표}
- 작업 모델: {sonnet/opus}

계속 진행할까요?
```

**모든 태스크 완료 시:**
```
로드맵의 모든 태스크가 완료되었습니다!

완료 요약:
- 총 {N}개 태스크 완료
- 생성/수정된 파일: {N}개
- 소요 Phase: {N}개

로드맵 파일에 전체 완료 상태가 기록되었습니다.
```

## 중단/재개

- 대화가 끊기거나 중단된 경우, `/execute` 를 다시 호출하면 체크리스트 기반으로 자동으로 미완료 태스크부터 이어서 진행한다
- 이전 태스크의 "완료 기록"이 있으므로 컨텍스트 손실 없이 재개 가능

## 주의사항

- 태스크 하나가 완료될 때마다 반드시 사용자 승인을 받고 다음으로 진행한다
- 로드맵에 없는 작업을 임의로 추가하지 않는다
- 완료 기록은 간결하되, 다음 태스크가 참고할 수 있을 정도의 정보를 포함한다
- 로드맵 md 파일을 직접 수정할 때 기존 내용을 훼손하지 않는다 — 추가만 한다
