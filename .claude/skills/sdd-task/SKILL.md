# SDD Task 실행기

당신은 SDD 워크플로우의 태스크 실행자입니다.
로드맵 MD 파일에서 다음 미완료 태스크를 찾아 실행하고, 완료 후 인수인계 기록을 남깁니다.

## 인자

- `$ARGUMENTS` — 로드맵 파일명 또는 태스크 번호 (선택)
  - `/sdd-task` — 가장 최근 로드맵의 다음 미완료 태스크 실행
  - `/sdd-task trgt-mgnt` — 특정 로드맵 지정
  - `/sdd-task trgt-mgnt 3` — 특정 로드맵의 특정 태스크 지정

---

## 실행 절차

### 1단계: 로드맵 파일 탐색 및 확인

1. `$ARGUMENTS`가 없으면 `docs/roadmaps/` 디렉토리에서 가장 최근 수정된 로드맵 파일을 찾습니다.
2. `$ARGUMENTS`에 키워드가 있으면 파일명에 해당 키워드가 포함된 로드맵을 찾습니다.
3. 로드맵 파일을 읽고 전체 구조를 파악합니다.
4. **사용자에게 로드맵 파일이 맞는지 확인합니다**:

```
## 로드맵 파일 확인

다음 로드맵 파일로 작업을 진행합니다:

📄 **{docs/roadmaps/YYYY-MM-DD-roadmap-{name}.md}**
📋 메뉴명: {메뉴명}
📊 전체 태스크: {N}개 (완료: {X}개 / 대기: {Y}개)

이 로드맵이 맞습니까? (다른 로드맵을 원하시면 파일명을 알려주세요)
```

**사용자가 확인하면** 2단계로 진행합니다.
다른 로드맵을 지정하면 해당 파일로 다시 1단계를 수행합니다.

### 2단계: 진행 상황 및 다음 태스크 표시

로드맵에서 **상태가 ⬜(대기)인 첫 번째 태스크**를 찾습니다.
(`$ARGUMENTS`에 태스크 번호가 지정되었으면 해당 태스크를 대상으로 합니다.)

사용자에게 다음을 보여줍니다:

```
## 현재 로드맵 진행 상황

📄 파일: docs/roadmaps/YYYY-MM-DD-roadmap-{name}.md

| # | Task | 상태 |
|---|------|------|
| 1 | Task 1 설명 | ✅ 완료 |
| 2 | Task 2 설명 | ✅ 완료 |
| 3 | **Task 3 설명** | **🔄 다음 실행 대상** |
| 4 | Task 4 설명 | ⬜ 대기 |

### Task 3: {제목}
- 목표: {작업 목표}
- 범위: {파일 목록 요약}
- 추천 모델: {모델}

이전 태스크 참고사항:
- {이전 완료 기록의 "다음 태스크 참고사항"}

이 태스크를 시작할까요?
```

사용자가 승인하면 3단계로 진행합니다.

### 3단계: 태스크 실행

1. **로드맵의 해당 태스크 상태를 🔄로 업데이트**합니다.
2. **태스크의 "작업 범위"에 명시된 파일들을 기준으로** 작업을 수행합니다.
3. 작업 중 아래 규칙을 준수합니다:

#### 필수 준수 규칙

- `CLAUDE.md`의 핵심 규칙 (레이어드 아키텍처, 도메인 격리, apiClient, 타입, Alembic 등)
- `server/CLAUDE.md`의 백엔드 패턴 (BaseService 상속, Repository 패턴 등)
- `client/CLAUDE.md`의 프론트엔드 패턴 (Zustand, apiClient 등)
- 참고 구현: `server/app/examples/sample_domain/`, `client/src/domains/sample/`

#### 작업 중 판단이 필요한 경우

요구사항이 모호하거나 설계 결정이 필요한 경우:
- **즉시 사용자에게 질문**합니다 (추측하여 진행하지 않음)
- 질문 형식: "A와 B 중 어느 방식으로 구현할까요? A의 장점은 ~, B의 장점은 ~"
- 불확실한 부분은 **제안을 함께 제시**합니다

### 4단계: 태스크 완료 처리

태스크 작업이 끝나면 **반드시** 아래를 수행합니다:

#### 4-1. 검수 체크리스트 실행

태스크의 검수 체크리스트 항목을 하나씩 확인하고 결과를 사용자에게 보고합니다:

```
## 검수 체크리스트 결과

- [x] 레이어드 아키텍처 준수 — Router → Service → Repository 구조 확인
- [x] 타입 힌트 누락 없음 — 전체 파일 확인 완료
- [x] Alembic 마이그레이션 파일 생성 — `alembic/versions/2026-03-26-add-xxx.py`
- [ ] ⚠️ `api/v1/router.py` 라우터 등록 — 다음 태스크에서 진행 예정

확인이 필요한 항목이 있습니다. 검토 후 진행할까요?
```

#### 4-2. 로드맵 MD 업데이트 (인수인계 기록)

로드맵 파일의 해당 태스크 섹션을 업데이트합니다:

1. **전체 Task 요약 테이블**의 상태를 `✅`로 변경
2. **해당 태스크의 완료 기록** 섹션을 채움:

```markdown
### 완료 기록

- **완료일**: 2026-03-26
- **변경 파일**:
  - `server/app/domain/{name}/models/__init__.py` (생성)
  - `server/app/domain/{name}/schemas/__init__.py` (생성)
  - `alembic/versions/2026-03-26-add-xxx.py` (생성)
- **커밋**: `a1b2c3d` — {커밋 메시지}
- **다음 태스크 참고사항**:
  - {설계 결정 사항, 원래 요구사항에서 변경된 점 등}
  - {다음 태스크에서 주의할 점}
- **미해결 이슈**: 없음 (또는 구체적 이슈 기술)
```

3. **검수 체크리스트**의 체크 상태를 실제 결과로 업데이트

#### 4-3. 커밋

변경된 코드를 커밋합니다. 커밋 메시지 형식:
```
[SDD] {메뉴명} - Task {번호}: {태스크 제목 요약}
```

#### 4-4. 완료 보고 및 다음 태스크 승인

```
## Task {N} 완료

커밋: {해시} — {메시지}
로드맵 업데이트 완료: docs/roadmaps/YYYY-MM-DD-roadmap-{name}.md

### 다음 태스크 미리보기

| # | Task | 설명 | 추천 모델 | 상태 |
|---|------|------|----------|------|
| {N+1} | {제목} | {설명} | {모델} | ⬜ 대기 |

남은 태스크: {M}개

**다음 태스크(Task {N+1})를 바로 시작할까요?**
검토가 필요하시면 검토 후 `/sdd-task`를 실행해주세요.
```

**사용자가 "예/진행/시작" 등으로 승인하면** 2단계로 돌아가 다음 태스크를 실행합니다.
**사용자가 "아니오/나중에/검토" 등으로 답하면** 세션을 종료합니다.

---

## 모든 태스크 완료 시

마지막 태스크가 완료되면:

```
## 모든 태스크 완료!

로드맵: docs/roadmaps/YYYY-MM-DD-roadmap-{name}.md
총 {N}개 태스크 완료

테스트 시나리오를 작성할까요?
(docs/test-scenarios/YYYY-MM-DD-test-scenario-{name}.md)
```

사용자가 승인하면 `CLAUDE.md`의 테스트 시나리오 작성 규칙에 따라 작성합니다.
