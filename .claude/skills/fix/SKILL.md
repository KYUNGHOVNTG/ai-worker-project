# 오류 수정

대상: `$ARGUMENTS`

## 수정 절차

### Step 1. 증상 수집

인자로 충분한 정보가 전달되지 않았으면 아래 정보를 사용자에게 질문한다:

```
오류 정보를 알려주세요:

1. **어떤 메뉴**에서 발생하나요? (메뉴 경로 또는 화면명)
2. **어떤 증상**인가요? (예: 조회 안됨, 저장 시 에러, 화면 깨짐 등)
3. (선택) **에러 메시지**가 있으면 붙여넣기 해주세요
4. (선택) **콘솔/네트워크 탭 스크린샷**이 있으면 첨부해주세요
5. (선택) **재현 절차**가 있으면 알려주세요 (어떤 순서로 조작하면 발생하는지)
```

### Step 2. 원인 분석

수집된 정보를 기반으로 관련 코드를 탐색하고 원인을 분석한다.

**분석 범위:**
- 에러 메시지의 스택 트레이스 → 파일:라인 추적
- 해당 메뉴의 프론트엔드 코드 (`client/src/domains/{name}/`)
- 해당 메뉴의 백엔드 코드 (`server/app/domain/{name}/`, `server/app/api/v1/endpoints/{name}.py`)
- 관련 공통 모듈 (`server/app/shared/`, `client/src/core/`)

**분석 결과 출력 형식:**

```markdown
## 원인 분석 결과

### 증상
- {사용자가 보고한 증상 요약}

### 원인
- **근본 원인**: {핵심 원인 1줄}
- **상세 설명**: {원인에 대한 설명}
- **관련 파일**:
  - `파일경로:라인` — 설명
  - `파일경로:라인` — 설명

### 영향 범위
- {이 오류가 영향을 미치는 다른 기능이나 화면}
```

### Step 3. 수정 계획 + 모델 추천

원인 분석을 바탕으로 수정 계획과 추천 모델을 제시한다.

**모델 추천 기준:**

| 추천 모델 | 조건 |
|-----------|------|
| **sonnet** | CSS/스타일 수정, 단순 CRUD 오류, 타입 에러, import 누락, 단일 파일 수정, 오타 수정 |
| **opus** | 다중 파일 연쇄 수정, 복잡한 쿼리 로직, 비즈니스 규칙 변경, 아키텍처 변경 수반, 원인이 불명확하여 깊은 분석 필요 |

**수정 계획 출력 형식:**

```markdown
## 수정 계획

### 수정 사항
| # | 파일 | 변경 내용 | 유형 |
|---|------|-----------|------|
| 1 | `파일경로` | 변경 설명 | 수정/추가/삭제 |

### 추천 모델: **{sonnet 또는 opus}**
- 이유: {추천 이유 1줄}

### 예상 영향
- {수정 후 예상되는 동작}
- {사이드 이펙트 가능성}

---
진행할까요? (Y/N)
```

### Step 4. 수정 실행

사용자가 승인하면 수정을 진행한다.

**수정 후:**
- 변경된 파일 목록과 변경 내용 요약 출력
- 테스트 방법 안내 (어떤 화면에서 어떤 동작을 확인해야 하는지)

## 주의사항

- 수정 전 반드시 관련 파일을 읽고 분석한다 — 읽지 않은 파일을 수정하지 않는다
- CLAUDE.md 규칙을 준수하여 수정한다 (SQLAlchemy 2.0, text() 바인딩 등)
- 수정 범위를 최소화한다 — 오류와 무관한 리팩토링, 주석 추가, 스타일 변경 금지
- `str(e)`를 HTTPException에 넣지 않는다 → `ApplicationException` 사용
