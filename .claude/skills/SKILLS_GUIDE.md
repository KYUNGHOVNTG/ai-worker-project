# Claude Code 스킬(Skills) 활용 가이드

> 스킬이란 무엇인지, 어떻게 사용하고, 프로젝트에 맞게 커스텀 스킬을 만드는 방법을 안내합니다.

---

## 스킬이란?

스킬은 Claude Code에서 **슬래시 커맨드(`/`)로 호출하는 자동화된 작업 절차**입니다.
반복적인 작업을 표준화된 절차로 정의해두면, 매번 같은 지시를 하지 않아도 일관된 결과를 얻을 수 있습니다.

```
/feature 회원관리      → 요구사항 정의 + 로드맵 생성
/execute               → 로드맵의 태스크를 순서대로 실행
/fix 로그인 안됨       → 원인 분석 + 수정 계획 제시
/code-review           → 변경된 코드의 규칙 위반 검사
```

---

## 현재 프로젝트의 스킬 목록

| 스킬 | 호출 | 용도 |
|------|------|------|
| **feature** | `/feature {기능명}` | 새 기능의 요구사항 정의서 작성 → 로드맵 MD 생성 |
| **execute** | `/execute {로드맵명}` | 로드맵 기반 태스크 순차 실행 (태스크별/일괄 선택 가능) |
| **fix** | `/fix {증상}` | 오류 증상 수집 → 원인 분석 → 수정 계획 + 모델 추천 |
| **code-review** | `/code-review {파일}` | 빌드 오류 + 프로젝트 규칙 위반 검사 |
| **make-doc** | `/make-doc {타입} {이름}` | 로드맵, 테스트 시나리오, 가이드, 보고서 등 문서 생성 |

---

## 추천 워크플로우

### 새 기능 개발

```
/feature {기능명}    →  요구사항 정의 + 설계 검증 + 로드맵 생성
         ↓
/execute             →  태스크 실행 (태스크별 또는 일괄)
         ↓
/code-review         →  완성된 코드 검토
         ↓
/make-doc test-scenario {이름}  →  테스트 시나리오 작성
```

### 버그 수정

```
/fix {증상 설명}     →  원인 분석 + 수정 계획
         ↓
(승인 후 수정 실행)
         ↓
/code-review         →  수정 코드 검토
```

---

## 프로젝트 성격별 추천 스킬

### 웹 서비스 프로젝트 (이 프로젝트처럼)

| 스킬 | 필요도 | 이유 |
|------|--------|------|
| feature | 필수 | 기능 단위로 요구사항 → 로드맵 → 구현까지 체계적 관리 |
| execute | 필수 | 로드맵 기반 태스크 순차 실행, 대화 끊겨도 이어서 가능 |
| fix | 필수 | 오류 수정 시 원인 분석부터 체계적으로 |
| code-review | 권장 | 커밋 전 빌드 오류 + 규칙 위반 자동 검사 |
| make-doc | 권장 | 테스트 시나리오, 보고서 등 문서 표준화 |

### 라이브러리 / SDK 프로젝트

추천 스킬: `code-review` (API 호환성 검사), `make-doc` (API 문서), `fix`

### 데이터 파이프라인 프로젝트

추천 스킬: `fix` (파이프라인 장애 분석), `execute` (마이그레이션 단계별 실행)

### 1인 사이드 프로젝트

추천 스킬: `feature` + `execute` 조합만으로 충분. 무리하게 많은 스킬 만들지 않기.

## 커스텀 스킬 만들기

### 스킬 파일 구조

```
.claude/skills/{skill-name}/SKILL.md
```

하나의 폴더에 하나의 `SKILL.md` 파일이 스킬의 전부입니다.

### SKILL.md 기본 템플릿

```markdown
---
name: my-skill
description: "이 스킬이 하는 일을 한 줄로 설명. Claude가 자동 매칭할 때 이 설명을 참고합니다."
disable-model-invocation: false
user-invocable: true
argument-hint: "[argument-description (optional)]"
---

# 스킬 제목

인자: `$ARGUMENTS`

## 절차

### Step 1. {첫 번째 단계}

{Claude가 수행할 작업을 구체적으로 기술}

### Step 2. {두 번째 단계}

{다음 작업}

## 주의사항

- {지켜야 할 규칙}
```

### 프론트매터 필드 설명

| 필드 | 필수 | 설명 |
|------|------|------|
| `name` | O | 스킬 이름 (슬래시 커맨드로 사용됨: `/name`) |
| `description` | O | 스킬 설명. Claude가 자동 매칭에 활용 |
| `user-invocable` | O | `true`면 사용자가 `/name`으로 직접 호출 가능 |
| `argument-hint` | - | 호출 시 인자 힌트 (예: `[filename]`) |
| `disable-model-invocation` | - | `true`면 Claude가 자동으로 이 스킬을 호출하지 않음 (명시적 호출만) |

### 스킬 작성 팁

1. **절차를 명확히** — "분석한다"보다 "git diff로 변경 파일을 확인하고, 각 파일의 변경 내용을 읽는다"
2. **출력 형식을 정의** — 결과물의 마크다운 템플릿을 스킬 안에 포함하면 일관된 출력
3. **사용자 확인 시점을 명시** — "이 시점에서 사용자에게 확인한다"를 명시하지 않으면 Claude가 임의로 진행
4. **주의사항에 금지 행동 기재** — "코드를 직접 수정하지 않는다" 등 경계를 설정
5. **프로젝트 규칙 참조** — "CLAUDE.md 규칙을 따른다"처럼 기존 규칙과 연결

### 예시: 간단한 커스텀 스킬

**배포 전 체크리스트 스킬** (`deploy-check`):

```markdown
---
name: deploy-check
description: "배포 전 최종 점검. 빌드, 테스트, 마이그레이션 상태를 확인합니다."
user-invocable: true
---

# 배포 전 점검

## 절차

### Step 1. 빌드 확인
- 백엔드: Python import 에러 없는지 확인
- 프론트엔드: `tsc --noEmit` 통과 여부

### Step 2. 미적용 마이그레이션 확인
- `alembic current`와 `alembic heads` 비교

### Step 3. 환경 변수 확인
- `.env.example`에 있는 키가 `.env`에도 모두 있는지

### Step 4. 결과 리포트
체크 결과를 테이블로 출력한다.
```

## 스킬 관리 요령

- **너무 많이 만들지 않기** — 자주 쓰는 5~7개면 충분. 쓰지 않는 스킬은 삭제
- **스킬 간 역할 분리** — 하나의 스킬이 너무 많은 일을 하면 나누기
- **프로젝트가 바뀌면 스킬도 업데이트** — 아키텍처나 규칙이 바뀌면 스킬도 수정
- **스킬 이름은 짧고 직관적으로** — 매번 타이핑하므로 2단어 이내 권장
